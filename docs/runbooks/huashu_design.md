# Huashu Design Runbook

## Goal

Produce reusable huashu assets that are structurally sound before they are stylistically polished.

## Input Packet

Capture these fields first:

| Field | Why it matters |
|---|---|
| Audience | Determines what value proposition can lead |
| Offer | Defines the main commercial hook |
| Delivery surface | Controls density and line length |
| Placeholders | Keeps the asset reusable across brands or advisors |
| Hard constraints | Prevents rewrites that silently break approvals or layout |

## Execution Sequence

1. reduce the request into audience, offer, channel, and placeholders
2. decide the message hierarchy before drafting final wording
3. write the primary line first and keep it visually compact
4. add only the minimum secondary support needed to make the offer understandable
5. separate optional proof, disclaimers, or advisor notes from the main selling path
6. if the result is visual, validate that the copy blocks can fit the intended composition without dense overflow

## Output Checklist

- primary line is scannable in one pass
- replaceable fields are explicit
- secondary copy is short enough for the channel
- optional comparison block is clearly separated
- CTA and contact block are concise and non-duplicative
- approval-dependent claims are marked instead of implied

## Escalation Conditions

- compliance-sensitive claims need approval
- the user asks for universal policy from one channel-specific asset
- the copy depends on factual guarantees not supplied in the prompt
